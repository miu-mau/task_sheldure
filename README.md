# Дипломное название проекта 

*Проектирование и разработка распределённого планировщика задач бизнес-процессов технического отдела финансовой организации*

## краткое обьяснение темы:

Планировщик принимает задачи из вне через gRPC от пользователя или от других сервисов. Потом он сохраняет их в бд, потом по условию или, например, по условному расписанию он их отправляет в очередь. Уже потом сервисы с этой очереди забирают себе задачи  и выполняют их меняя статус задания после завершения.

## Инструменты для реализации планировщика


*Язык и среда*: Go (Golang) — основной язык разработки.


*Взаимодействие сервисов*: gRPC


*Хранение данных*: PostgreSQL (или SQLite для простоты демонстрации).


*Очередь сообщений*: RabbitMQ или Go-channels.


*Планирование задач*: cron или robfig/cron


*Мониторинг и логирование*: Logrus или встроенный log в Go.


*Тестирование*: testing в Go. gRPC можно тестировать через grpcurl или Postman.


*Инфраструктура*: Docker/docker-compose

## Обязательный минимум для диплома

1. gRPC API (обязательно реализовать)
   - Методы: CreateTask, GetTask, ListTasks, CancelTask, CreateSchedule.
   - `request_id` в метаданных для трассировки и базовой идемпотентности (повторные CreateTask не создают дубликаты).

2. Хранилище в PostgreSQL с миграциями
   - Таблицы: `tasks` (id, payload, status, created_at, updated_at, scheduled_at, attempt, last_error), `schedules` (id, cron, enabled, created_at), `attempts` (id, task_id, started_at, finished_at, status, error).
   - Индексы по `status`, `scheduled_at`, `created_at`; внешние ключи; транзакции.

3. Планировщик заданий
   - Использовать robfig/cron для чтения активных расписаний и постановки задач в очередь по времени.
   - Фоновый цикл, который переводит готовые к исполнению задачи в очередь с учётом дедлайнов.

4. Очередь сообщений (распределённость)
   - RabbitMQ как основной вариант (exchange/queue/binding), формат сообщения с `task_id` и `request_id`.
   - Гарантии: подтверждение публикации, DLQ или простая стратегия повторной публикации при сбое.

5. Воркер-исполнитель (референсный сервис)
   - Подписывается на очередь, исполняет задачу (mock/HTTP вызов), по завершении вызывает gRPC для смены статуса и записи попытки.
   - Обработка ошибок и повторов с базовым backoff (например, экспоненциальный до N раз).

6. Модель статусов и ретраи
   - Статусы: draft → queued → running → success | failed | cancelled.
   - Политика повторов: максимум попыток, backoff, фиксация `attempts` и `last_error`.

7. Идемпотентность и консистентность
   - Базовая идемпотентность CreateTask по паре (request_id, payload hash) или уникальному ключу.
   - Атомарные переходы статусов (optimistic locking/версионирование записи задачи).

8. Наблюдаемость и эксплуатация (минимум)
   - Структурированные логи (уровни, поля: request_id, task_id, status).
   - Healthcheck endpoints (liveness/readiness) для планировщика и воркера.
   - Простой счётчик выполненных/ошибочных задач (в логах или минимальные метрики).

9. Безопасность (минимум для защиты API)
   - Авторизация по статическому токену в gRPC-метаданных, проверка на сервере.
   - Дедлайны и лимиты на RPC (context deadlines/timeouts).

10. Docker/docker-compose для локального стенда
    - Контейнеры: PostgreSQL, RabbitMQ, Scheduler, Worker.
    - Makefile/скрипты для миграций, запуска сервисов и начального наполнения.

11. CI (минимум)
    - GitHub Actions: линт (`golangci-lint` при наличии) и `go test ./...`, проверка генерации gRPC.

12. Демонстрационный сценарий
    - Скрипт/шаги: поднять стенд, создать задачи (включая по расписанию), наблюдать переходы статусов и обработку воркером, показать отмену/ретраи.

## Этапы реализации проекта

1. Инициализация репозитория и базовая структура
   - Создать модуль Go (`go mod init`).
   - Определить базовую структуру каталогов: `cmd/`, `internal/`, `pkg/`, `api/`, `deploy/`.
   - Подключить базовые зависимости (логирование, конфиги, миграции, gRPC, cron, драйвер БД, RabbitMQ).

2. Проектирование доменной модели и требований
   - Сформировать перечень сущностей: `Task`, `Schedule`, `Workflow`, `Attempt`, `Worker` и статусы задач.
   - Описать жизненный цикл задачи и переходы статусов (draft → queued → running → success/failed → retry/cancelled).
   - Определить SLA/ретраи: политики повторов, backoff, дедлайны, идемпотентность.

3. Проектирование API (gRPC)
   - Описать proto-контракты: создание задачи, получение статуса, отмена, листинг, планирование по расписанию.
   - Добавить в контракты поля трассировки (request_id), метаданные, дедлайны.
   - Сгенерировать серверные и клиентские стабы, включить в CI проверку совместимости API.

4. Схема БД и миграции
   - Спроектировать таблицы: `tasks`, `schedules`, `attempts`, `outbox` (опционально), индексы и уникальные ключи.
   - Добавить миграции (up/down) и локальный bootstrap БД.
   - Определить ограничения целостности и внешние ключи, индексы по статусам/времени/идемпотентным ключам.

5. Конфигурация и инфраструктура
   - Структура конфигов: порт gRPC, DSN БД, RabbitMQ, параметры планировщика, лимиты ретраев.
   - Добавить загрузку конфигов из env/файлов (12-factor), валидацию.
   - Базовые Dockerfile + docker-compose для `postgres`, `rabbitmq`, `scheduler`.

6. Реализация хранилища (repository layer)
   - CRUD для задач, атомарные переходы статусов с оптимистичной блокировкой/версионированием.
   - Квитирование попыток выполнения и хранение результатов/логов.
   - Запросы под очереди (выборка готовых к постановке задач) с блокировкой на выборку.

7. Реализация gRPC сервиса
   - Внедрить методы: CreateTask, GetTask, ListTasks, CancelTask, CreateSchedule, ListSchedules.
   - Идемпотентность по `request_id`/`idempotency_key`.
   - Метрики, логирование, трейсинг middleware, валидация входных данных.

8. Планировщик (scheduler loop)
   - Механизм проверки расписаний (robfig/cron) и публикации задач в очередь по времени.
   - Фоновый воркер по изменению статусов задач согласно условиям (deadline, retry, зависимые шаги).
   - Настройка конкуррентности, backoff стратегий, защита от дублей.

9. Интеграция с очередью сообщений
   - Подключить RabbitMQ (объявление exchange/queue/binding), форматы сообщений.
   - Публикатор задач: преобразование `Task` → сообщение, сохранение корреляционных данных.
   - Обработать подтверждения/ошибки публикации, DLQ политика.

10. Воркеры-исполнители (reference implementation)
   - Пример сервиса-подписчика, который получает задачи, исполняет и отчитывается о результате через gRPC.
   - Протокол подтверждения выполнения: UpdateTaskStatus/ReportAttempt.
   - Образцы для разных типов задач (mock вычисление/HTTP вызов).

11. Мониторинг и наблюдаемость
   - Метрики Prometheus: количество задач по статусам, время постановки/выполнения, ретраи, ошибки.
   - Логирование (структурированное) и трассировка (OpenTelemetry), кореляция request_id.
   - Healthchecks/liveness/readiness endpoints.

12. Тестирование
   - Unit-тесты для репозиториев, сервисов и планировщика.
   - Интеграционные тесты с реальным Postgres и RabbitMQ (через docker-compose profile).
   - Контрактные тесты gRPC (buf/evans/grpcurl), тест кейсы на идемпотентность и гонки.

13. Безопасность и надежность
   - Аутентификация/авторизация gRPC (mTLS/токены) — базовая реализация.
   - Ограничение запросов (rate limiting), квоты, дедлайны RPC.
   - Механизмы дедупликации, транзакционность, обработка сбоев при публикации.

14. Сборка и поставка
   - Makefile/Taskfile для сборки, тестов, линтинга, генерации кода.
   - Мультистейдж Dockerfile, оптимизация размеров образов.
   - docker-compose для локального запуска всего стенда.

15. CI/CD
   - Настроить пайплайн: линт, тесты, генерация proto, сборка образов, загрузка артефактов.
   - Кэширование зависимостей, отчет о покрытии, публикуемые метрики.

16. Нагрузочное тестирование и профилирование
   - Сценарии нагрузки: массовое создание задач, всплески расписаний, волны ретраев.
   - Профилирование CPU/heap, устранение основных узких мест.
